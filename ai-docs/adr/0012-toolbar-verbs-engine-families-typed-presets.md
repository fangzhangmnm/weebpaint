# ADR-0012：工具栏放动词，动词绑 engine 族，preset 按 engine 族 typed（「动词原则」）

> created 20260906 · 作者 Claude Fable 5.1（claude-fable-5-1）
> 状态：**已决定**（user 2026-09-06「同意。动词原则进 adr」）· 落地：分轮（UI 抽象轮 / 手指自己的笔架 / 智能橡皮各自另案）

## 背景

2026-09-05 晚评审：手指（smudge）借滤镜笔架、强度默认值是 controller 常量、模糊笔误读笔间距（v0.13.4）导致强度与成本耦合——
三件事同一个病根：**工具与笔的路由没有模型**。user 提出两个 competing 模型并都判「不完全对」：

- **⊗ 模型**：`preset.engine ∈ {paint, smudge, filter, clone, shape?} × tool ∈ {freehand, shape, lasso, fill, picker}`。
  user：「嗯和我想的差不多，但是其实可能很多 UI 的混乱反而是这个模型……⊗ 的问题在于会有很多死 parameter，比如刚刚造成过混乱的间距」。
- **全展开模型**：把 ⊗ 展开成「只有笔：选区笔、smart color bucket 笔、填色笔、模糊笔、克隆笔……」。
  user：「其实我觉得这样也不对，但是其实这样蛮接近艺术家世界观」。

约束：**zen / distraction free 是名片**（user：「我们的名片之一就是 zen/distraction free，而不是 krita 那种的 a380 仪表盘」）。
Krita 的 paintop preset × tool 两轴只作参考，不照搬。

## 决定

1. **工具栏放动词**（你的手在做什么），不放 engine、不放 preset：`笔 · 橡皮 · 手指 · 套索`（+ 菜单/保存 | fx/图层/颜色 三个面板位）。
2. **动词绑 engine 族**，切动词才换族；动词内换 preset 只换手感：
   - 笔 = paint 族，子工具 freehand / shape（**形状笔是同一把笔的另一种走法，preset 字段完全相同**）。
   - 橡皮 = paint 族，子工具 普通 / 整笔智能擦（后者待做，UI 先留位）。**橡皮是动词**，即使实现上复用画笔（user：「橡皮是动词，即使再能用画笔复用也是动词」）。
   - 手指 = 涂抹族，子工具 手指 / 混色 / 模糊 / 锐化 / 液化 / 克隆，各自图标（user：「以后可以滤镜笔都搬家到手指这个 tool 栏位。每种都有一个自己的图标。用户可以切换」）。
   - 套索 = 选区族，子工具 套索 / 魔棒 / 矩形 / 选区笔 / 填色（user：「油漆桶进套索试一下吧」；ADR-0004 的「填色与选区不互通」语义不变——切子工具就是切工具，只是共用图标位）。
3. **preset schema 按 engine 族 typed**：涂抹族 preset 没有 spacing/streamline 之类 paint 族字段，死参数结构上消失；每个动词记自己的当前 preset（现有 toolStates 形状）。
4. **子工具经长按 + 角上小三角**（user：「小三角试试吧，不 zen，多了一个 visual distraction，但是 catsup (sketchup clone) 必然会小三角。blender 也小三角」）：动词位图标随当前子工具换，子工具专属工具条只在该子工具活着时出现。
5. **上下文工具条来源 = 当前工具 ∪ 当前图层类型**：文字/矢量图层选中即出对应工具条，不设文字 tool（user：「文字图层矢量图层用不同的工具栏，而不是一个文字 tool」）。
6. **吸色不是工具**：撤顶栏图标；长按画布（现默认开）+ 左栏非工具钮 + 色板吸管 + 渐变条直接吸；吸到的颜色走 color target 栈落到当前编辑目标（笔色 / 待填色 / 选中色标）。

## 理由

- 工作流观察（user 2026-09-06）：「你要么是形状笔和橡皮，要么是画笔和橡皮。反而不太会在形状笔和画笔之间切，这就是为什么形状笔和画笔可以进一个 slot」——最高频的来回切必须在顶栏一格内完成，所以橡皮是动词；不常切的收进子工具。
- 形状笔作笔的一个模式在逻辑上完美但「最高频的画画的时候不够 zen」（常驻一条 freehand/shape 条）——小三角 + 子工具条按需出现解掉这个矛盾。
- typed preset 直接消灭「间距事故」一类死参数；每族有自己的间距语义（模糊 = wash 幂等、手指 = 特征长度 / 连续形式，见 grill 议程 §C/§E）。

## 不做 / 待另案

- 不做全 ⊗、不做全展开；不做 Krita 式仪表盘。
- 智能橡皮（逐笔擦）需要每笔归属图（stroke id map / 矢量侧车），另案；这里只留橡皮位的第二个子工具。
- 落地顺序 = UI 抽象轮（context-toolbar 深模块 + 子工具长按标准件 + 顶栏 9 格 + 断点表）→ 手指自己的笔架/出厂笔（typed preset 第一刀）→ 智能橡皮。策划稿见 `ai-docs/20260906-ui-abstraction-round-proposal.md`（现状 .h + 提案 .h）。

## 修订 2026-09-06 晚：吸色钮拍板（user 原话）

- 「好那么先加吸色按钮吧，不要像procreate一样谜语人就一个方框，而是用我们的吸管。你的提案先试一下。先很没有创意的放两个滑条中间吧我建议是一次性。按住形式容易误触碰，也是为什么我不太喜欢procreate这个设计的原因。然后根据context不同也许可以变成别的icon」
- 「仿制图章的时候就是需要变语义吧」
- 落成（v0.13.12）：左栏两滑条之间 `#leftPick`（吸管图标，一次性：tap 进取样态，取一次回**原工具**，再 tap = 取消）；色板 HEX 行加吸管钮；I 键同一语义；Alt+笔 / 画布长按仍是临时取色不进模式；顶栏吸色钮撤。**按住式不做**。钮的图标/语义由 context 派生（LeftDialOpts.getPickIcon/onPick 是接口）：现在只有吸色；克隆子工具落地时 = 定源点。
