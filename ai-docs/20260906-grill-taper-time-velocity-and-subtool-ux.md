## 0. 墨点案：大笔刷落笔顿一下产生墨点（v0.13.15 已修，手感变动请上手裁）

**问题陈述**（家规：手感类先写清输入输出）：输入 = 平涂（size 50、sizeCoeff 1、pressureLPF 50ms、taperIn 0.5）落笔后原地顿住 ~0.5s（按压力涨到 1）再以压感 0.3 起步；输出 = 起步后前半个笔宽的 dab 尺寸。旧行为：前 25 doc px 内 dab 迅速涨到满压 50px 的粗头（墨点），而不顿直接起步是 ~12px 的细头。

**病根**（考古 `ai-docs/20260604-stroke-smoother-time-gate.md`「弧长看不见顿」+ `backend/brush.ts`）：压感 LPF 走**事件时间**（τ=50ms），taper-in 走**弧长**（长度 = size×taperIn，flat 25px / ink 4px）。顿住时：LPF 已涨到按压力、strokeDist 仍为 0；起步后 taper 在半个笔宽内放开 → 满压粗头。首颗 dab 本身很小（钉在落笔压感），墨点是起步那一小段。**不是压感曲线的退化**：v0.13 的四档/曲线都在这条链上游，判据不变；这是 v33（2026-05-27）立 taper-in 那天起就有的结构差（当时 Pencil 落笔 spike 用 taper 压，没考虑顿）。

**修法**（`backend/brush.ts extendStroke` 一行判据 + `stroke-smoother.ts wouldMove` / `PressureLPF.rebase`）：死区锚没离开落笔点前，LPF 只对钟不积压感；起步时从落笔压感起追 → 顿多久都等于没顿。测试 `test/brush-dwell-pressure.test.mjs`：顿 30 样本 vs 不顿，起步后前 60px dab 尺寸逐颗一致；起步后真按重仍变粗；顿住期间不撒点。pixel（immediate）路径不动；smudge 引擎无 taper 无 LPF 不涉及。

**手感代价**（user 上手裁）：落笔时「先按重再走」不再被记住——起步压感从落笔那一瞬起算。真按重的话 LPF 3τ≈150ms 追上，与不顿的起笔完全同形。若 user 想要「顿 = 积墨」（自然媒介语义），那是 §3 速度→压感 的事，不该由 LPF 偷偷提供。

## 1. 考古事实（out-tap 为何关、taper 现在到底是什么）

- **out-tap 关掉的唯一人类出处**：user 2026-07-23「勾线笔的 end taper 误事，在笔刷库里面关掉」（journal/20260723 v0.5 onward tasks.md:29）。**没有任何进一步解释**（翻遍 journal / ai-docs / git log：无 lag、无手指鼠标、无 hover、无预测的讨论）。v0.5.3（`f284619`）把 user 自己手调笔架的 diff 回灌 builtin：勾线 out 0.5→0、**平涂 in/out 0.3/0.3 → 0.5/0**——平涂的 taperOut=0 不是工程决定，是 user 自己旋钮的值。
- **2026-05-27 设计时不做 out-tap 的两个理由**（`ai-docs/20260527-brush-design.md:138-148`）：① 抬笔时机不可知、回溯 messy；② 「Pencil 物理压感抬笔本来就掉到 0，抬笔端已自然 fade」——**② 只对笔成立**，手指/鼠标恒压 → 这正是 user 今天的点。v161（2026-06-03）实装 out-tap 用的是「抬笔后干走一遍量总长再回溯」，即理由 ① 被接受了。
- **taper 现在是压感包络**（`brush.ts _stampParams`：taper 乘的是 p，再进 gamma/曲线）：
  - `opaCoeff = flowCoeff = 0` 的笔（平涂、勾线）taper **只能变细不能变淡**；`sizeCoeff = 0` 的 fixed 变体 taper 完全无效（`src/brushes.ts:118-119` 明文）。
  - 长度 = size × taper（弧长）：flat 25 doc px、ink 4 doc px，都不到半个笔宽。
  - floor 0.4 在 gamma 之前乘：勾线 gamma 0.5 把 floor 抬回 65% 宽——尖端是截头不是尖。
  - 点一下（tap）两端 taper 乘同一颗 dab → p×0.16（两端都开的笔：硬橡皮、刷子、selPen 硬圆）。
  - out-tap 只在抬笔后回溯出现：预览钝头、抬笔一跳变尖（回溯改的是最后 size×taperOut px）。
- **时间制的先例**：2026-06-02 立、06-12 user 拍板砍掉的「时间门」（`ai-docs/20260604-stroke-smoother-time-gate.md`）：「笔速应该是调平滑力度，不应该有时间门……时间门的机制完全把 W 给毁了」。砍的是「慢 = 少平滑」这个反号语义；但位置平滑（SmoothDamp）与压感 LPF 本身都是时间制且留着——**时间做滤波合法，时间做平滑强度的门非法**，这是先例的准确边界。
- **速度→线宽的先例**：`ai-docs/20260613-brush-procreate-smoothing.md:89-90` backlog「顿感 → 线宽（手速驱动，慢→粗 = 马克笔/毛笔积墨）」+ 20260613-brush-proposal.md:220-224 外部咨询原话「让线宽跟手速走，顿就自然浮现」。注意：它预言的正是 §0 刚修掉的那种粗头——**顿 = 墨点在那条 backlog 里是 feature**。

## 2. Grill：in/out tap 按时间结算

先把「时间结算」定义清楚（两种都能叫时间制，语义相反）：

- **T-a 起步钟**：入端 env = min(1, 起步后经过时间 / T_in)；出端 env = min(1, 距抬笔剩余时间 / T_out)。
- **T-b 落笔钟**：入端从 pointerdown 开钟（顿住期间 taper 自己放开）。

**T-b 直接把 §0 的墨点请回来**（顿 0.5s → 入端早已放开 → 起步满压）。所以时间制入端只能是 **T-a，且「起步」的判据 = §0 那同一个 wouldMove**——两件事天然是一件事，这是这轮最省心的巧合。

Q1 **快甩长尾、慢停无尾**——这是时间制的核心红利：抬笔前最后 T_out ms 走过的弧长就是尾巴长度。勾线故意停在交点再抬笔 → 尾巴几乎零长（不削线头，正对「误事」）；甩出去的发丝 → 长尾。user 要确认：**「误事」的内容是不是「故意停下的线头被削细」**？如果 2026-07-23 的痛点其实是别的（比如尾巴形状抬笔一跳），时间制不治那个。

Q2 **这算复活时间门吗？** 我的判断不算：时间门改的是中段平滑强度且反号；时间制 taper 只作用于两端、中段零影响、语义 =「速度定尾长」。但它和被砍的时间门共用一个直觉「慢 = 故意」，需要 user 明确划线，不然三个月后又会被当成时间门砍。

Q3 **包络乘什么？** 现状乘 p（压感包络）。对手指/鼠标（p≡0.5 或四档 none 时 p≡1）、对 opa/flow coeff 为 0 的平涂勾线，taper 乘 p 只能变细、不能变淡；fixed 变体完全无效。**如果 out-tap 的目标用户是手指/鼠标玩家，那 taper 必须能独立乘 size 与 alpha**（`taperSize` / `taperAlpha` 两个系数，或 taper 直接作用于 dab 尺寸与不透明度而非 p）。这是手感红线的结构改动，要 user 一句话拍板方向；数字仍归 user。

Q4 **预览一致性**：出端 taper 只能在抬笔后回溯（时间制更是），Procreate 也是抬笔才出尾巴。接受「抬笔一跳」吗？替代 = 预览也画一条「假设现在抬笔」的尾巴（每帧对 tail 段施包络）——`ai-docs/20260601-brush-frozen-tail-smoothing.md:237` 当年提过，代价是 live 尾巴一直是尖的、看起来像还没画完。

Q5 **floor 与 tap**：时间制天然想要 floor→0（真尖）；但点一下（tap）是 T=0 → 入端 env=floor → floor=0 就画不出点。需要「tap 例外」：单 dab / 总时长 < T_in 的笔画不吃入端（或 floor 只对 tap 生效）。

Q6 **T_in / T_out 数字**：起点提议 T_in 60–80ms、T_out 80–120ms（一帧到两帧的手速），单位 ms 而不是 size 倍数；per-brush 存字段 → `taperIn/taperOut` 语义从「size 倍数」换成「ms」= **笔架数据迁移**（存量用户笔 taper 0.5 会变成 0.5ms=无效）。要么新字段（`taperInMs`，旧字段留着当 legacy 距离制），要么一次性换算迁移（0.5×size px ÷ 典型手速）。倾向新字段 + 旧字段保留：笔刷可选「距离制/时间制」，出厂笔切时间制。

Q7 **flat / sketch / ink 默认开 out-tap**（user 提议）：**没有「sketch」这支笔**（builtin 里是铅笔 pencil / 刷子 bristle）；平涂 out=0 是 user 自己的手调值（§1）。建议：时间制落地后，出厂笔开 out T_out，**但 -fixed 变体不开**（fixed = 机械均匀线，同形状笔 ADR-0005 的理由）。

## 3. Grill：velocity → pressure（手指/鼠标玩家）

Q1 **方向**：两派相反——毛笔/马克笔「慢→粗（积墨）」（2026-06-13 backlog 的方向）vs 数字工具惯例「快→细」（CSP/SAI 的速度影响 size 都是快甩变细，慢画粗）。其实同一个映射：**速度大→压感小**。但「慢→粗」的极限就是「顿→墨点」= §0 刚修掉的现象。**user 必须先答：墨点是 bug 还是 feature？** 我的建议：对**有真压感**的笔，速度不介入（真压感优先，顿不是墨点——§0 成立）；对**无压感输入**（mouse、finger、四档 none）速度当合成压感，此时顿 = 墨点是自然媒介语义、是 feature。两条互不打架。

Q2 **放在哪一层**：`input.ts effectivePressureFor` 之后、引擎之前，与四档（`common/pressure-level.ts shapePressure`）同层——四档加第五档「速度」：`p = curve(v_screen / v_ref)`。同一 pressure 通道 → 画笔 / 手指 / 滤镜笔 / 选区笔全自动受益，引擎零改动。

Q3 **速度的量纲**：屏幕速度（screen px/ms，手的物理速度）而不是 doc 速度（随 zoom 变）。要先 LPF（τ≈50ms，与压感 LPF 同钟）不然抖。v_ref 起点 ≈ 1 screen px/ms（慢描）… 5 px/ms（快甩）。

Q4 **曲线**：直接复用 `common/anim-curve` + `ui/curve-editor`（压感曲线深模块已在）：velocity→pressure 的曲线 = 一条 AnimCurve，编辑器现成；默认 = 快→细的 ease。

Q5 **鼠标 0.5 常量**：现状 mouse p≡0.5。有了速度档，鼠标默认走速度档还是留 0.5？倾向：速度档 opt-in（设置页压感四档旁），默认不变，避免 nudge 存量手感。

Q6 **与时间制 taper 的耦合**：两者都是「速度决定形状」，但一个作用全程（速度档）、一个只作用两端（taper）。同时开时，快甩 = 全程细 + 长尾——叠加合理，不需要互斥。

**建议的落地顺序**（等 user 逐条回复后）：① 速度档（四档→五档，opt-in，曲线复用）② 时间制 taper（新字段、T-a 起步钟 = §0 判据、包络可乘 size/alpha）③ 出厂笔开 out-tap（fixed 不开）。①②互不依赖。

## 4. 小三角双语义（user 第 8 条「同一个按钮有两个下拉语义」）

**问题的准确形状**：顶栏动词位现在 = tap（切动词，带记忆的子工具）+ 长按（选子工具）；子工具的**选项**（形状条 / 套索条 / 滤镜笔条上的 variant 下拉 + 旋钮）又在第二条工具条。「选子工具」与「子工具选项」分别在两个地方，且长按不可见。

**提案 A：「再点一次 = 展开子工具」替代长按**（Procreate 的原生习惯：再点一次当前工具 = 打开它的库）。tap（未激活）= 切动词；tap（已激活）= 弹子工具菜单（图标 + 文字，走我们的 popup-menu，不用原生 select）；长按保留为快捷（可有可无，随时可撤）。双语义变成「一个按钮、一个动作、两种状态」——这是 Procreate 用户已经有的肌肉记忆，也不杀我们的（顶栏位置不变）。小三角只作「这里有子工具」的静态提示。

**提案 B：第二条 = 左边选子工具、右边子工具选项**（user 自己想的）。缺点 user 已说：笔和橡皮不够 zen。补救：**默认子工具且无选项 → 第二条整条不出现**（笔·自由手 / 橡皮 = 零第二条，与现在同 zen）；第二条只在「子工具 ≠ 默认」或「子工具带选项」时出现（形状笔 / 套索 / 滤镜笔本来就有条）。这样 B 的 zen 代价其实为零——只是把「选子工具」多放了一个入口在第二条左端。**A 和 B 可以同时成立**：顶栏再点 = 弹菜单（首选入口），第二条左端 = 同一菜单的第二入口（有条的时候顺手）。

**fx 的语义回到 filter**（同意 user）：模糊/锐化/液化/马赛克是「手指」的子工具（已经在动词位长按里），不该再列在 fx；fx 只留 region filter（调整 / 艺术滤镜）。随之：滤镜笔条上的 variant 下拉退役（选子工具走顶栏），条上只剩**选项**（揉匀 / 稀释 / 记忆 / 混色空间 / 笔架 / ✓）。

**图标 vs 文字**：子工具菜单项 = 图标 + 文字（popup-menu 支持），顶栏位只显图标。滤镜笔的名字确实要文字（模糊 / 锐化 / 液化 / 马赛克 图标区分度低）——菜单里有文字就够了，条上不再重复。

**形状笔 = 子工具还是 toggle**：user 自己也摇摆。我的判断：矩形 / 圆 / 直线是**画什么**（动词的对象），「自动对齐」是**怎么画**（修饰）。前者当子工具（现状），后者是另一个 feature（吸附/snap，CatsUp 那边正在做的东西以后可借），别合并成一个 toggle——合了以后「对齐的自由手」和「不对齐的矩形」都表达不出来。

**最高频子工具的 zen**：默认子工具就是最高频的（笔·自由手 / 手指·手指 / 套索·自由套索），一 tap 到位，第二条不出现；非默认子工具本来就要多一步。这条原则写进 ADR-0012 的修订即可。

**z-order**：popup-menu 走 band 表（`--z-*`），顶栏菜单已经是它在管，不需要新深模块；若 A 落地时撞到 floating-window 抢 z，再按 UI 抽象轮流程抽。

**建议**：A 先做（一天内，风险 = 长按用户的肌肉记忆——目前只有 user 一个，且长按可保留）；B 的「第二条左端入口」随形状/套索条重做（U5 全量）时顺手；fx 语义回 filter + 条上 variant 下拉退役与 A 同批。等 user 一句「没问题」。
