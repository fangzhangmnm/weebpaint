## 0. 一句话

录一个**单元**（unit：一段笔触序列，不是像素——荷叶边一波、一颗纽扣、一颗星、一个负重轮），再拖一条路径，单元沿路径**阵列 + 变形**地被**真的重画**出来。放大旋转不失真，因为鹦鹉学的是笔触矢量，不是贴图。
user：「所以就是一个矢量版的 selection to brush texture」「可以说是非常厉害的自动人偶了」。

缘起：Claude WebUI 的嘲讽——「别人的 lo 裙是维多利亚时代机器生产的堆叠。你用手追荷叶边画的想吐是正常的」。user：「怒了。proposal：鹦鹉笔，我们做一个自动缝纫机出来」。

## 1. 名字候选（user：「叫缝纫机笔也行。或者更 historical accurate 的那种专门绣花或者做某种装饰性布料的机器」）

| 候选 | 机器 | 贴切处 | 别扭处 |
|---|---|---|---|
| 鹦鹉笔 | — | 学舌 = 重放；已是 user 口头名 | 不 historical |
| 缝纫机笔 | 家用缝纫机 | 人人认识 | 缝纫机不做装饰花样 |
| **花边笔** | Leavers 花边机（1813，英国诺丁汉） | 维多利亚时代机器蕾丝**就是它**——嘲讽里那台机器；lo 裙花边的祖宗；normie 词 | 只指花边这一种用途 |
| **提花笔** | Jacquard 提花机（1804，穿孔卡片） | 「记下花样→机器沿布重复」= 录制→重放的语义本体；可编程机器的祖宗；normie 词 | 提花是织进布里，不是缝在布上 |
| 绣花笔 | Schiffli 飞梭绣花机（1863） | 绣在布面上 | 词太泛（绣花 = 任何刺绣） |

AI 倾向：**花边笔**（出身故事 + 嘲讽里的那台机器）或 **提花笔**（语义最准）。两个都过「低调 normie」那条命名美学。定名归 user。

## 2. 拆成三个正交件（施工时就按这个切）

### A. 单元 Unit —— 录下来的东西

- **内容 = 笔触序列**（tagged union，将来还能加 kind）：
  - 自由手笔触：笔刷引用 + 采样点（x, y, 压感, 倾斜, 时间）+ 颜色 + 笔设置快照 + **随机种子**（抖动/纹理要可复现）；
  - 形状笔 op：kind + 参数（圆/矩形/透视框……）——user：「形状笔最好也支持，可以做多铆蒸钢八对负重轮之类的」；重放时按参数化放大，不是把圆采样成折线；
  - （以后）像素 stamp：selection→brush 的那种，也是 unit 的一个 kind——同一个放置器能吃（见 §6）。
- **OBB**：局部坐标系（原点、u 沿向、v 横向、半长宽）。默认 = 录下笔触的主轴（PCA）；用户可转可拉。user：「同时可能有一些 obb (bbox + rotation) 的配置」。
- **录制时 undo 弹栈**：user：「录制的时候用户 undo 的也不用傻乎乎的记录画 + undo，而是同样弹栈」→ unit = op-log 的一个切片；录制器听 ADR-0008 的令牌 commit / undo，不是截屏。
- 单元跨图层？录制时笔触落在多层（线稿层 + 阴影层）—— v1 拍平到当前层；跨层复现很强但复杂，列为开放问题 §8-4。

### B. 放置器 Placer —— 单元怎么落到画布上

放置器只依赖 unit 的「局部点 → 画布点」变换接口，不看 unit 内容。

1. **沿曲线阵列**（荷叶边的本体）：拖一条路径 → 弧长参数化 → unit 的 u 映到弧长 s（周期 = OBB 长 × 间距系数），v 映到法向偏移 × 宽度系数。user：「你拖一笔呗，就是 array along curve with deform」。
2. **线性阵列 N 份**（八对负重轮）：两点 + 数量。
3. **单次 stamp**：点一下放一个（纽扣）。
4. **scatter**（星星、气球）：user：「这个其实等我们以后做 texture 笔、scatter 笔之后就自然会做了」——放置器共用，那时顺手。

### C. 重放器 Replayer —— 真的画出来

- 变形后的每笔逐笔喂给**现有笔刷引擎**（不走贴图）：dab 间距在变形后的路径上重算，所以放大不失真、笔触质感保真。
- **确定性**：同 unit + 同变换 + 同种子 = 同像素。CPU/GPU 两条笔刷路径都要有 seeded RNG。这是 multiplayer 也要的性质。

## 3. 变形数学（沿曲线阵列）

- 路径 P(s)、切向 T(s)、法向 N(s)。unit 局部 (u, v) → P(s) + v·w·N(s)，s = u·k。k = 沿向缩放、w = 横向缩放，**独立**（user：「各向异性放大比例（长宽压缩）」）。
- **conformal weight** c ∈ [0,1]（user 原词）：控制 dab 形状跟不跟局部 Jacobian。c = 1 → dab 保持圆，半径只按 √det J 缩放（保角）；c = 0 → dab 完全跟随 J（沿向 k、横向 w 的椭圆）。中间 lerp。前提 = 引擎 dab 支持椭圆；不支持就退化成「半径取方向加权」（§8-5）。
- **曲率修正**：弯道内侧被压缩、外侧拉伸；用 (1 + v·κ(s)) 因子（κ = 曲率）修正横向，或者干脆接受折叠（布料本来也会叠）。
- **伪 3D 扭转（荷叶边的灵魂；user：「思考一下能不能做一些伪 3d 的扭转效果」）**：加周期相位 φ(s) = 2π s/λ。横向 v′ = v·cos φ（布片转向时横向压扁）；cos φ < 0 时 unit 镜像（看到背面）——背面可以是正面镜像、也可以让用户录一个「背面 unit」、再或者按 |cos φ| 调暗当简单光照（§8-3）。再进一步 u 按 sin φ 微错位模拟透视。λ / 幅度可以吃拖动时的压感或速度 → 这就是 user 的「根据你拉动的过程实时重复画画过程」。
- **重采样**：unit 里的直线笔触跨过弯道必须弯——变形前每笔按 ≤ 2 px 弧长重采样，再变换，再交给引擎（引擎自己再做 spacing）。

## 4. 实时复现（自动人偶）

user 2026-09-07 澄清：「我说的重放就是根据你笔移动的位置，循环播放你录制的笔触，不是一笔一笔落，而是你可以看到拖动的时候鹦鹉也在画，而不是一整笔。不过这个纯属宣发花活，可以加一个禁用选项以节省性能，不过我觉得其实不太伤性能。因为你还是 60 帧」。

- **进度由笔的位置驱动（scrub，不是定时器）**：拖到弧长 s，就把当前周期内的进度 (s mod L)/L 映射到录制的播放进度（按录制笔触的累计长度或笔序），鹦鹉画到哪取决于你的笔在哪——往回退就倒带。看到的是鹦鹉**一笔一笔跟着你画**，不是整个 unit 一下子蹦出来。
- **成本**：每帧新画的 dab 数 = 这一帧笔走过的弧长对应的录制 dab 数，与用户手画同量级（本来就是 60 帧在画）——user 判「不太伤性能」，AI 同意。**倒带 / 路径后编辑**才是贵的那档（scratch 层局部重画）。
- **禁用选项**：关掉 = 单元按周期整份落地（或松手一次性重放），留给弱机。默认开——它是宣发画面。
- 路径整体形状变（后编辑）就整段重画到预览 scratch 层；超预算时降级为只画笔触骨架（细线预览），松手再全量重放。
- 提交 = 一个 history point：一次 undo 撤掉整条花边。
- 路径要不要贝塞尔把手后编辑（像曲线工具那样）——看曲线工具现状（§7 现状核实）。

## 5. 生命周期 = 计算器的 M+ / M− / MR / MC（user 心智模型）

user：「我很怕污染 global namespace……最喜欢的心智模型是计算器的 M+ M- MR MC 的级别的。而不是会用一个『新建笔刷-你没有给我起名字』的姿态跟着你一辈子……快速建 pattern，快速用，迭代重做。而不是变成 asset store mindset。不过一定的记忆也是要有的。自定义形状也按照这个政策。」

- **少量无名槽**（比如 4 个）：M+ 录进当前槽（追加）/ MR 用 / MC 清 / 覆盖不问名字。不进笔架、不走「新建笔刷」流程、没有资产库页面。
- **「一定的记忆」的归属**（待 user 拍板，§8-2）：跟画走（`.ora` 的 `.weebpaint/` 里一个 KB 级 json——**ora 布局变更要上报 + 附目录表**，家规）还是跟设备走（device-kv 最近 N 个）——荷叶边 unit 属于这条裙子，AI 倾向跟画走，设备再留最近几个。
- **自定义形状**（形状笔 custom shape）同政策，同槽机制。

## 6. 和 selection→brush texture 的关系（user 问：「有了鹦鹉笔之后是不是不用 selection to new brush 了？」）

AI 答：**不是取代，是同一个放置器的两种 unit**。像素 unit 仍有三种用武之地：① 带渐变 / 混色 / 湿边的**成品质感**（笔触序列重放不出「画完后又抹过」的结果）；② 导入的图 / 扫描件；③ 重放太贵的重单元（几百笔的花样，像素 stamp 是 O(像素) 一次，重放是 O(笔 × dab)）。反过来矢量 unit 的优势 = 放大旋转不糊、笔触质感随当前笔刷走、可以变形。所以：**放置器共用，unit 分矢量 / 像素两 kind，两个功能一次做完**；生命周期政策（§5）对两种一视同仁。

## 7. 与录制纪元 / multiplayer 的关系——铺路还是制造混乱（user 的顾虑）

- **现状**（2026-09-07 读码，subagent 对账）：
  - timelapse 录的是**帧**（`src/backend/timelapse/` + `src/timelapse-session.ts`：~2 s 采样、H.264 mp4 随 .ora 走 `.weebpaint/timelapse.mp4`），零笔触数据，不可重渲染。
  - **没有整笔数据类型**：笔刷引擎是流式的 `beginStroke → extendStroke(x, y, pressure, t) → endStroke`（`src/backend/brush.ts`），落地件 = `collectStamps()` 的 dab 集；采样只有 (x, y, 压感, t)，**全仓无倾斜/方位角**。跨引擎契约 = `StrokeEngine`（`src/backend/stroke-session.ts`）。
  - 形状笔：参数只活在瞬态引擎里，抬手即像素（`src/shape-brush.ts` 头注释：「是笔…不是带 gizmo 的可编辑对象」）；几何走 `src/shape-geometry.ts` 折线化。**画布上可编辑路径的曲线工具不存在**（v0.12 台账仍列 long requested）——鹦鹉笔的路径编辑和曲线工具是同一件事，谁先做谁铺路。
  - undo = 令牌 + collector（ADR-0008），撤的是像素 / 结构 delta，不是笔触。
  - **好消息：引擎里零 `Math.random`**（ADR-0009 决定论：stainedGlass 抖动都是确定性 hash）——重放确定性几乎白送，只要将来加抖动/纹理时守住「seed 进 StrokeRecord」。
- 三个消费者共用一个底座 = **「笔触即数据」（StrokeRecord）+ 确定性重放**：multiplayer（op 流）、矢量 timelapse（回放画画过程，可换分辨率）、鹦鹉笔（unit）。
- **铺路（安全、小、随时可做）**：定义可序列化的 StrokeRecord + `replayStroke(record, transform, target)` + 确定性测试（同种子同像素）。不碰 UI、不建槽、不做变形。就算 multiplayer 永远不做也不亏——它只是把「一笔」变成一个值。
- **混乱（别做）**：没有 StrokeRecord 就先做录制 UI / 槽位 / 阵列变形；或者为鹦鹉笔给引擎开专用入口。
- **顺序**：录制纪元（StrokeRecord + 矢量回放）→ 鹦鹉笔（unit + 放置器 + 变形）→ scatter / texture 笔（星星气球自然到手）。user 已说「可以先做录制纪元」。

## 8. 开放问题（施工前要 user 一句话；**现在不问**）

### 8-0. 难点：怎么一笔画连起来（user 2026-09-07 点名：「鹦鹉笔的难点是怎么一笔画连起来，这个进待议」）——**待议**

**问题陈述**（输入 / 输出）：输入 = 单元 U（局部坐标 u ∈ [0, L] 上的有序笔触）+ 路径 P(s)；输出 = 沿 P 重复 N 份后，**穿过单元边界的笔触在相邻两份之间读成同一笔**——荷叶边的下摆是一条连续的波浪线，不是 N 段各带起笔收笔 taper、接缝处重叠一颗 dab 的短线。岛状笔触（纽扣）没这个问题；贯穿笔触（下摆线、缝线、饰边）全靠这条。

**拆开看是四个小问题**：

1. **录制时怎么知道哪些笔触是贯穿的、怎么接**：
   - 自动判：端点落在 OBB 的 u 边缘 ε 内的笔触 = 贯穿笔触；右出口与左入口按 v 值配对。多条贯穿线 v 接近时会配错。
   - **周期画布**（AI 倾向）：录制时 OBB 左右显示幽灵副本（无缝贴图编辑那种），笔画穿过右边缘就从左边缘绕回来（u 取模 L）——接缝是用户自己的笔连续画过去的，光滑是构造出来的，不用配对。单元里存的是未取模的笔触（u 可以超过 L）。
   - 不解决：接缝处关 taper + 重叠一点。效果差，作为兜底档。
2. **重放时怎么合成一笔**：贯穿笔触在 N 份之间**串成一条长笔触**（采样点首尾相接，dab 间距连续算，只在整条路径的两端 taper）；接缝两侧压感 / 速度不一致时在周期末尾/开头各 ~5% 交叉淡入。每条贯穿笔触各自成链。
3. **路径长度不是 L 的整数倍**：a) 拉伸 k 让 N 份刚好铺满（Illustrator 图案笔刷的 stretch-to-fit）；b) 截断最后一份（贯穿链在路径末端自然 taper；装不下的岛状笔触整颗丢或按质心判）；c) 起止帽单元（Illustrator 有 start / end / corner tile 三种，我们第一版不做）。**闭合路径**（裙摆是环！）是最理想的情形：k 微调让 N·L·k = 周长，链首尾相接，根本没有端点。
4. **急转弯**：贯穿链在强曲率处折叠；用户拖的是手画路径本来就光滑，第一版接受折叠，不做 corner tile。

**先例**：Clip Studio Paint 装饰笔刷的「リボン（ribbon）」模式——笔尖图像沿笔画拉伸接成连续一条带，二次元圈的蕾丝笔刷几乎全是它做的（像素版）；Illustrator 图案笔刷（side / start / end / corner tile）与艺术笔刷（一个单元拉满整条路径 = 我们放置器的第 5 种模式：单根羽毛、一条丝带）。我们 = CSP ribbon 的笔触矢量版：接的是笔触不是贴图，所以 dab 沿接好的链重算，放大不糊。

1. 名字（§1）。
2. 槽数、记忆归属（跟画 / 跟设备 / 两者）。
3. 荷叶边背面：镜像正面 / 用户录背面 unit / 按 |cos φ| 调暗。
4. 跨图层 unit（线稿层 + 阴影层一起复现）v1 做不做。
5. 引擎 dab 椭圆支持——conformal weight 的实现下限。
6. 形状笔 unit 的参数化放大规则（圆的半径跟 k 还是 w 还是 √(kw)）。
