## The false "newer version in the cloud" conflict is gone

Refreshing the page shortly after a save could leave the painting without its sync lineage; the next
upload then looked like a name clash and the gallery showed a conflict sheet even though nobody had
touched the cloud copy. The sync library (now 2.2.1) checks the cloud first and re-attaches the lineage
when the cloud copy is still the one it last saw. If something really does need a decision, the gallery
now shows a visible **Resolve…** button on that card and a "needs attention" list at the top, and each
file is settled one at a time in the library's own sheet — nothing is pushed or overwritten in bulk.

## Remember the gallery password on this device

Opt-in, for up to 30 days; forgotten when you lock the gallery or sign out. The password panel is now a
real form, so Edge and Chrome can offer to save the password as well. The single-file and itch builds
leave this feature off (they share storage with other pages on the same origin).

## Uploads survive a refresh

Large uploads (over 4 MB) record their session and continue after a refresh or after iOS puts the page to
sleep. A push that hangs after the iPad locks now times out instead of blocking autosave, and a failed
chunk is retried on its own.

## Your paintings and newer versions of WeebPaint

Each part of the file (the painting, the desk layout, brush racks, time-lapse recordings) now carries its
own version. A painting written by a slightly newer WeebPaint opens and saves without losing the parts
this version does not understand; one written by an incompatible version is refused rather than
overwritten. The old "this painting was saved by a newer app — overwrite?" warning is back and now also
guards autosave and background sync, not only manual saves.

## Reference window

Video references, with frame-by-frame stepping. Audio and video references are kept in memory for the
session only, so they do not bloat the painting file. Any reference card can be shrunk to a small round
button and dragged out of the way.

## Smaller things

- The page runs only its own scripts (a Content-Security-Policy without `eval`).
- Settings → Developer has **Factory reset…** (two-step confirmation): it clears only WeebPaint's own data
  and offline files, nothing belonging to sibling apps. "Force update" likewise touches only WeebPaint's
  caches.
- After signing in, if some paintings have not been uploaded yet, a notice says how many and offers
  **Resolve** instead of pushing them for you.
- The gallery's old "push to cloud" button is retired; everything goes through the resolve sheet.
