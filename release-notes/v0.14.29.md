## Clipping masks now work on top of a layer group

A layer clipped to a **group** now clips to everything in that group, the way it always did for a single
layer (and the way the design said it should). Groups in any blend mode or opacity work as a base; the
mask uses the group's own content, not the group's opacity. **If an old painting had a clipped layer sitting
on a group, it will now look clipped** — that is the intended look, which the GPU renderer had been skipping.

## The selection follows a transform

Moving, scaling or rotating a selection no longer throws the selection away. While the content floats there
is no selection; when you apply, the selection comes back in the new place and shape, and if you cancel it
comes back where it was. The deselect button no longer disappears after a transform.

## Undo bookkeeping, fixed at the root

The earlier fix for "undo wipes the history after Split colors" treated one symptom. The pixel history is now
tracked by the identity of each layer's pixel store rather than by its position in the layer tree, so creating,
writing and deleting layers inside one undo step can no longer disagree about order. A randomized test over
layer operations guards it.

## Smaller things

- The layer **⋯** menu's *Split colors* and *Clear* items no longer stay greyed out after importing an image and
  applying the transform.
- Cloud sync library update: saving while a sync push is still in flight can no longer leave the file marked as
  synced when it is not.
